# Agent 14 — Numerical Atlas & Reproducibility Harness

This directory is the reproducibility backbone for the 4-body 2+/2−
investigation. It consolidates every distinct initial condition used by
Agents 5–9 into a single master CSV, and provides a Julia harness that
re-runs each row and compares against the stored result.

Files:

- `atlas.csv` — master table (50 rows, ~40 with recoverable ICs).
- `reproduce.jl` — re-runs the atlas via `shared/run_survey.jl`.
- `NOTES.md` — this file.

## Schema

One row per distinct IC. Columns:

| Column          | Meaning |
|-----------------|---------|
| `id`            | Unique row identifier (keep stable across edits). |
| `agent`         | Originating agent number (5, 6, 7, 8, 9). |
| `family`        | Dynamical family (e.g. `breathing_square_L0`, `rotating_square`, `dimer_dimer`, `collinear_abab`, `ftl_regime`, `poincare`, `lyapunov`, `sub_weber_D`). |
| `config_name`   | Name of the `shared/ic_generators.jl` builder when recoverable. |
| `n_particles`   | 4 throughout. |
| `dims`          | 2 or 3 (all current rows 2D). |
| `masses`        | JSON flat array, length `n_particles`. |
| `charges`       | JSON flat array, `[+q,+q,-q,-q]`. |
| `c`             | Speed of light in simulation units. |
| `dt`            | Integration step. |
| `tmax`          | Final time. |
| `zollner_a`     | Zöllner mismatch parameter (0.0 = disabled). |
| `bounce_r`      | Collision-bounce radius (0.0 = disabled). |
| `q0_json`       | Flat position vector, length `n_particles*dims` (=8), JSON. Empty if unrecoverable. |
| `p0_json`       | Flat momentum vector, same length, JSON. |
| `retcode`       | Stored retcode string (`Success`, `Failure`, `partial`, `Unknown`). |
| `E_drift_pct`   | Stored global max energy-drift %, or empty. |
| `survival_time` | Longest bounded interval, or `-1` if not measured. |
| `bound`         | `true`/`false`. |
| `tags`          | Comma-separated free-form tags (quoted in CSV). |
| `notes`         | Free-form provenance note (quoted when containing commas). |

Commas inside `masses`, `charges`, `q0_json`, `p0_json`, `tags`, and
`notes` force double-quoting — the hand parser in `reproduce.jl` handles
this (including `""` escapes).

## Coverage

- **Agent 5** (`05_periodic_orbits/found_orbits.csv`): all 35 orbits
  imported with full `q0`/`p0`. Covers `breathing_square_L0`,
  `rotating_square`, `dimer_dimer`, `collinear_abab`,
  `collinear_abab_kick` families.
- **Agent 9** (FTL regime): 3 rows (`F1`/`F2`/`F3`) as config-name
  references. `q0`/`p0` omitted because they are generated
  parametrically inside `09_ftl_regime/ftl_experiments.jl` and were not
  written back to disk; the `notes` column records the exact generator
  call to replay.
- **Agent 6** (Poincaré): 4 representative config/energy_fraction rows
  (`two_dimers`, `rhombus`, `alternating_square`). ICs generated by
  `shared/ic_generators.jl` with an energy-fraction knob; not
  materialized to disk, so `q0_json`/`p0_json` are empty.
- **Agent 7** (Lyapunov): 3 representative rows; same situation as
  Agent 6.
- **Agent 8** (sub-Weber): 5 grid cells from the `ic_D` 5×5 scan. ICs
  reconstructed from the script's analytic `ic_D` layout (`[-r0/2, 0,
  r0/2, 0, ...]`). The two "far" negative positions are approximate:
  the original script placed them at `R_far=8.0` but with additional
  y-offsets we could not perfectly recover. See the per-row `notes`.

## Omissions

- All Agent 6/7 rows and Agent 9 rows lack explicit `q0_json`/`p0_json`
  and will be reported as `[SKIP]` by `reproduce.jl`. To materialize
  them, re-run the source scripts with a small patch that writes the
  flat IC vectors into a CSV, then paste those rows in here.
- Agents 1–4 and 10–13 produced no ICs (symbolic / theoretical /
  post-hoc analyses) and therefore contribute no rows.

## Running the harness

```bash
# Full replay (40 rows with stored ICs)
julia --project=. _research/Topology/FourBodyTwoPlusTwoMinus/14_numerical_atlas/reproduce.jl

# Only rows whose id matches a substring pattern
julia --project=. _research/Topology/FourBodyTwoPlusTwoMinus/14_numerical_atlas/reproduce.jl --subset F1b
julia --project=. _research/Topology/FourBodyTwoPlusTwoMinus/14_numerical_atlas/reproduce.jl --subset dimer
julia --project=. _research/Topology/FourBodyTwoPlusTwoMinus/14_numerical_atlas/reproduce.jl --subset D_r
```

The script prints `[PASS]` / `[FAIL]` / `[SKIP]` per row and a trailing
summary. A row is considered PASS if (a) the retcode string either
contains or is contained in the stored one, and (b) the measured
E drift is within 0.5 percentage points (or 10% relative) of the stored
value.

**This script is NOT executed by CI.** It exists as a manual
reproducibility tool. The author should rerun it after any change to
`src/solve.jl`, `src/weber_system.jl`, or `shared/run_survey.jl` and
check that PASS counts remain stable.

## Adding a new row

1. Assign a stable `id` (prefix with the agent number, e.g.
   `F5_something`).
2. Fill `agent`, `family`, `config_name` (if any).
3. Populate `masses`/`charges` as JSON flat arrays.
4. Populate `q0_json`/`p0_json` as JSON arrays of length `n*dims`.
   Leave empty only if the IC is parametric and not materializable.
5. Quote any field that contains a comma with `"..."`, doubling any
   embedded quotes.
6. Commit the CSV change and re-run `reproduce.jl --subset <id>` to
   verify the new row.

## Sanity check performed by Agent 14

`reproduce.jl` was loaded into Julia 1.12 (without running any
simulations) and used to parse `atlas.csv`. Result: 50 rows, 40 with
non-empty `q0_json`, all 21 columns resolved. The hand parser correctly
handles the quoted comma-containing fields.
