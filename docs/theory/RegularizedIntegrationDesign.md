# Regularized Integration Design for Weber Hamiltonian

## Scope

This document specifies the algorithmic design for adaptive close-encounter regularization in WeberElectrodynamics.

- Only Weber Hamiltonian systems generated by `WeberSystem` are supported.
- Regularization is optional per problem and enabled by default.
- Standard Cartesian integration remains the default far-field path.

## Public Configuration

Regularization is configured through `WeberProblem` keyword arguments:

- `regularization_enabled`
- `regularization_r_on`
- `regularization_r_off`
- `regularization_r_on_factor`
- `regularization_r_off_factor`
- `regularization_max_substeps`
- `regularization_constraint_tolerance`
- `regularization_g_floor`
- `regularization_chain_enabled`

When `regularization_r_on` or `regularization_r_off` are not provided, thresholds are derived from the initial minimum pair distance.

## Dispatch Logic

Each outer step performs:

1. Pair-distance evaluation for all particle pairs.
2. Encounter graph construction for pairs below threshold.
3. Active component update with hysteresis:
   - Activate when a minimum pair satisfies `r <= r_on`.
   - Keep active while component max distance is `<= r_off`.
   - Deactivate otherwise.
4. Mode choice:
   - Two-body component: pair mode.
   - Larger connected component with chain enabled: chain mode.
   - Otherwise: Cartesian mode.

## Pair Mode

For active pair 
\((i,j)\):

1. Build relative state from Cartesian variables.
2. Apply dimension-specific lifting:
   - 1D: square-map scaffold
   - 2D: Levi-Civita lift and projection identity checks
   - 3D: KS lift with bilinear constraint projection
3. Integrate with adaptive substepping (bounded by `regularization_max_substeps`).
4. Use the existing Cartesian projected step kernel for each substep.

## Chain Mode

For overlapping encounter components:

1. Build deterministic chain ordering by greedy nearest-neighbor links.
2. Compute chain monitor 
\(\Omega = \sum 1/r_{ij}\) over active component pairs.
3. Set monitor-based scale 
\(g = \max(1/\Omega, g_{\text{floor}})\).
4. Determine substeps from `dt/g`, capped by `regularization_max_substeps`.
5. Advance each substep through the Cartesian projected kernel.

## KS Constraint Handling

In 3D regularized paths:

- Lifted KS momentum is projected onto the bilinear-constraint manifold each substep.
- Maximum absolute constraint residual is tracked in diagnostics.

## Diagnostics Semantics

`RegularizationDiagnostics` tracks:

- activation/deactivation counts
- number of pair, chain, and Cartesian outer steps
- total and max substeps
- minimum encounter distance seen
- maximum KS constraint residual
- per-step mode history

Mode history encoding:

- `0`: Cartesian
- `1`: Pair regularized
- `2`: Chain regularized

## Memory Model

The implementation uses persistent buffers for:

- pair-distance and graph workspaces
- active component and chain ordering
- relative coordinate/momentum scratch
- LC/KS map and Jacobian scratch

No per-step heap allocations are required in regularization helper kernels.
